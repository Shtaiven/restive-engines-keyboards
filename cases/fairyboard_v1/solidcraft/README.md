# Fairyboard v1 case — SolidCraft models

These are the SolidCraft models of the `slim_case_with_walls` print parts (`../slim_case_with_walls/*.stl`), originally
generated from `../cad/*.scad`. The **PCB is the master**: the case and window are built by referencing PCB geometry
(its outline, drill holes and footprint pins). Shared values that are not on the PCB live in one parameter table.

## Files

| File | What it is |
|---|---|
| `fairyboard_pcb.sc` | **Master.** Main PCB from `pcbs/fairyboard_v1/fairyboard/fabrication` (Gerber outline + drills). Thickness `pcb_t`; placed in the case frame by `frame_x`/`frame_y`. |
| `fairyboard_plate.sc` | Switch-plate PCB from `pcbs/fairyboard_v1/fairyboard_plate/fabrication` (1.6 mm, silkscreen). |
| `fairyboard_bottom_case.sc` | Bottom case. Links `fairyboard_pcb.sc` (hidden reference). |
| `fairyboard_center_window.sc` | Center window. Links `fairyboard_pcb.sc` and the plate twice (hidden references). |
| `fairyboard_assembly.sc` / `.step` | Links everything for checking fit. The case and window are linked at identity, and the plate is linked ×2 via `plate_*`. |
| `fairyboard_params.csv` | The shared parameter table: every design imports it. |
| `sync_params.py` | Turns the CSV into SolidCraft batch files (see below). |
| `bottom_case.stl/.step`, `center_window.stl/.step` | Exports. The case is in the assembly frame. `center_window.stl` is at z 0 (print position); `center_window.step` is in the assembly frame (z 1.6). |
| `tools/` | Scripts used to generate the bottom case's outer-wall sketch (see "Outer wall"). |

## What references what

- **Case outer wall:** every line is parallel to a projected PCB edge at `pcb_clear + wall`. Every arc is tangent to its neighbours, with radius = PCB arc radius + `pcb_clear + wall` (via construction circles concentric with the PCB arcs). Concave corners are sharp, like OpenSCAD `offset(delta=)`. Top and bottom are filleted `fillet_r`.
- **Case PCB pocket / floor pocket:** projected PCB outline offset `+pcb_clear` / `−ledge_w`.
- **Case insert holes:** concentric with the PCB's 16 M2 holes, Ø `insert_d`.
- **SCUF recesses:** positioned from key-centre drill holes. The mid feet sit on the pinky-home key hole; the others are offset by `scuf_*_dx/dy` (mirrored) and turned by `scuf_*_rot`.
- **Case wall cutouts:**
  - power and reset: centred on their footprint pins, widths `pwr_cut_w` / `rst_cut_w`
  - terminal: from its first/last pins (`case_term_start`, `term_cut_end`)
  - all three: y extents from the PCB centre edges (`case_cut_in/out`)
- **Window lip (case):** `bump_w` wide, centred on the PCB centre section. Its ends stand `lip_proud` past the outer wall.
- **Window base:** top and bottom are the PCB centre-section edges. The flanks sit `pcb_clear` inside the plates' inner edges, so the window-to-plate gap equals the PCB-to-case gap. The right plate edge is the left one mirrored about `(plate_l_x + plate_r_x)/2`, because picks on the turned-over plate copy were unreliable.
- **Window bump / hollow / screen / USB-C:** centred on the PCB centre section. Overhang is `top_overhang`; the USB-C opening's height comes from the PCB top.
- **Window cutouts:** JST, wire channel and wire cover are placed from the JST pins; power, reset and terminal from their pins (as in the case). The mount holes are concentric with the PCB's window holes, Ø `win_hole_d`.
- **Heights:**
  - PCB on the case ledge at z 0
  - case top and plate top at `pcb_t + plate_gap + plate_t` (3.8)
  - window base `win_base_t` (2.2, as printed) hangs down from that height, so it rests on the case lip
  - the 0.4 mm gap under the window base is how the printed part fits

Verified against the original STLs (see `../slim_case_with_walls`):
- **Case:** every surface within 0.09 mm. The case outline is 0.0185 mm higher in y because it now follows the PCB's own outline, which is also why all holes line up.
- **Window:** within 0.084 mm (the flanks, which now follow `pcb_clear`).
- **Gaps:** both measure exactly 0.375 mm (`pcb_clear`).

## Editing

**Shared values** (`fairyboard_params.csv`):
1. Edit the CSV.
2. Run `python3 sync_params.py` to write `params_sync.json`.
3. In each design, run that file with the SolidCraft MCP `batch` tool (`path`). It applies every value in one rebuild.

New parameters must first be added to a design with `parameters.add` or `params_import.json`. Tested rebuilding cleanly: `pcb_clear`, `wall`, `insert_d`, `plate_gap`, `base_h`, `bump_w` and `win_hole_d`.

**PCB changes:** rebuild `fairyboard_pcb.sc` from new Gerbers, or move it with `frame_x/frame_y`. Then:
1. Run `component.update_links` in the case and window designs.
2. Then run it in the assembly.

Moving the PCB 1 mm was tested: the whole case followed exactly with no errors.

**Outer wall:** its sketch was generated by `tools/gen_wall.py` from the PCB outline topology (which edges are lines, convex or concave arcs). The four 1.9 mm PCB steps that vanish at this offset are dropped, as OpenSCAD's offset does. Positions follow the PCB and `pcb_clear + wall` through the constraints. If the outline's topology changes (edges added or removed), regenerate the sketch:
1. `tools/kicad_edge_cuts_to_dxf.py <kicad_pcb> tools/pcb_edge_cuts.dxf -211.7326 158.6689`
2. `tools/gen_wall.py tools <dxf> wall.json 1.975 "pcb_clear + wall" 0`

## Known limitation: "needs repair" on linked copies

SolidCraft stores a linked design as a STEP snapshot, declaring a 2e-5 mm uncertainty. Two kinds of linked copy fail its strict check after a reload and show "needs repair before it can be modelled":
- the Gerber board (4 vertex gaps), in every design that links it
- the bottom case, in the assembly

The cause is constraint-solver residuals at PCB-derived tangent joints and fillet blends, around 1e-4 mm. The source designs rebuild from history and are clean.

The references are only projected from and displayed, so nothing in this workflow models on them. Projection, interference checks and exports all work. If you need to model on the case inside the assembly, paste its history in rather than linking it.

All links point at the files in this folder, stored as relative paths, so they follow the repo. For an agent to read or relink them, the SolidCraft MCP server must be allowed this folder. It currently runs as `solidcraft-cli mcp --allow-path /home/steven/Projects`, set in `~/.claude.json`.
